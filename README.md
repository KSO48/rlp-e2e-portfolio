# E2E-автоматизация многошагового согласования (портфолио, выдержка)

Это выдержка из более крупного проекта: end-to-end автотесты на Playwright +
TypeScript для веб-портала с многошаговым процессом согласования документов
(создание заявления → назначение исполнителей → согласование на нескольких
уровнях → финальное решение), включающим реальное электронное подписание
документов.

Публикуется как демонстрация подхода к автоматизации, а не как рабочий
проект — реальные учётные данные, URL внутреннего стенда и часть сценариев
из полного репозитория намеренно не включены.

## Стек
- Playwright + TypeScript
- Кастомная сборка Chromium с GOST TLS + расширение-плагин для реального
  подписания документов (не мокается — тесты действительно подписывают)

## Что показывает этот код

- **`tests/dev_regress*.spec.ts`** — полные e2e-сценарии шести разных
  разновидностей процесса согласования (от создания заявления до финального
  статуса), построены на общих переиспользуемых шагах.
- **`tests/statementCreation.ts`, `tests/approvalChain.ts`,
  `tests/mzApprovalFlow.ts`** — общая библиотека шагов: устойчивые к гонкам
  гидратации клики (click → проверка эффекта → повтор force-кликом →
  скриншот и явная ошибка, если не помогло), поллинг с перезагрузкой
  страницы для кнопок, которые появляются после асинхронной обработки на
  бэкенде, работа с кастомными UI-компонентами (дропдауны с поиском, WYSIWYG
  редактор).
- **`tests/chromiumGost.ts`** — запуск браузера с нужным TLS/плагином +
  сквозной перехват ошибок страницы (`console.error`, необработанные
  исключения, HTTP-ответы ≥400, упавшие запросы) с логированием в реальном
  времени по ходу прогона — не нужно вручную лезть в DevTools, чтобы понять,
  что упало.
- **`tests/users.ts`** — управление сессиями нескольких ролей в одном
  тесте (переключение пользователя без потери состояния теста), с обработкой
  двух разных схем логина (форма на той же странице / редирект на внешний
  Keycloak).

## Что не включено
- Конкретный URL и реальные учётные данные тестового стенда.
- Полный набор сценариев (в исходном проекте — 6 услуг × 3 вида тестов ×
  2 стенда: smoke/regress/batch-прогоны).
- Тестовые документы-вложения.

## Запуск
Требует собственный Chromium-Gost + плагин КриптоПро (см. `.env.example`) —
без них не запустится, поскольку электронное подписание в этих тестах
настоящее, а не замоканное.

```bash
npm install
cp .env.example .env.local   # подставить свои пути/креды
npm run test:headed
```
